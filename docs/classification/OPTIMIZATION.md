# 성능 최적화 결과

## 변경

- CWE→OWASP 역방향 인덱스를 취약점마다 재구성하지 않고 리포트당 한 번 구성한다.
- 원본 탐지별 위험도를 한 번 계산해 대표 위험도 및 근거 목록에 재사용한다.
- 심각도별 집계를 여러 번 순회하는 대신 Counter로 한 번 집계한다.
- 정렬 시 등급 위치 검색 대신 사전으로 조회한다.
- 상세 결과 복사는 JSON 직렬화·역직렬화 대신 deepcopy를 사용한다. 호출자 변경으로부터의 격리는 유지한다.

매핑 파일은 리포트당 한 번 읽는다. 공유 변경 가능한 전역 캐시는 도입하지 않았다. 중복 통합 기준·ID·정렬 정책·응답 구조는 바꾸지 않았다.

## 실제 측정

Python 3.12.10, Windows에서 같은 프로세스로 목 데이터 5,000건을 최적화 전후 각각 5회 실행하고 중앙값을 비교했다. 입력 모델 생성 시간은 제외하며, 매핑 로드·중복 통합·분류·평가·집계·정렬을 포함한다.

- 이전: 0.312757초
- 이후: 0.177909초
- 약 1.76배 처리 속도, 소요 시간 약 43% 감소
- 전체 리포트 객체 동등성 확인: 통과
- 기존 자동 테스트: 51 passed in 0.46s

단일 환경의 목 데이터 측정이다. 실제 HTTP·DB·스캐너 성능이나 동시 요청 성능을 의미하지 않는다. 상세 조회 함수의 속도 개선은 별도로 수치 측정하지 않았다. 원시 측정값은 benchmark-results.json에 보관했다.
